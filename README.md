# 스티커 중심형 홍보스티커 점검 - 비교사이트

이 프로젝트는 기존 '차량 전체 기준사진 비교형'과 별도로 배포하는 A/B 비교용 사이트입니다.

## 핵심 차이
기존 사이트:
- 차량 전체 기준사진과 촬영사진 비교
- 차종/차색/촬영구도 영향이 큼

이 사이트:
- 스티커 종류별 정상 원본 관리
- 사용자가 차량사진에서 스티커 영역만 드래그
- 선택한 영역만 기준 스티커와 비교
- 차종/차색 영향 감소

## 주소
- 사용자: /check/
- 관리자: /admin/

## 데이터 분리
기존 Cloudflare D1/R2를 재사용하지만 별도 namespace를 사용합니다.

DB:
- st_stickers
- st_rules
- st_inspections

R2:
- sticker-compare/reference/
- sticker-compare/inspection/

기존 vc2_* 테이블이나 app-v2/ 파일을 수정/삭제하지 않습니다.

## 주의
이 버전은 외부 AI를 쓰지 않고 회사 보안환경에서 안정적으로 비교하기 위해
사용자가 직접 스티커 영역을 지정하는 방식입니다.
향후 원하면 AI 자동탐지형을 별도로 추가할 수 있습니다.


## V2 정밀 비교 알고리즘

기존 손상률 계산은 두 사진의 전체 윤곽선 개수를 비교했기 때문에,
스티커가 뜯어진 자리에서 새로 생긴 찢김 윤곽선이 오히려 '정상 특징'처럼
계산될 수 있었습니다.

V2는 다음 방식으로 변경했습니다.

1. 정상 기준 스티커에서 비교 가치가 있는 특징 블록만 추출
2. 촬영사진에서 각 기준 특징의 대응 위치 탐색
3. 정상적으로 남아있는 고신뢰 특징들로 위치/회전/미세 스케일 차이 보정
4. 보정된 위치에서 기준 특징이 실제 남아있는지 재검사
5. 서로 인접한 기준 특징이 연속적으로 사라진 영역만 손상률에 크게 반영
6. 찢어진 자리에 새로 생긴 선이나 차량 반사는 기준 특징으로 인정하지 않음
7. 기준사진과 선택영역 종횡비가 크게 다르면 확인필요 경고

'손상률'은 실제 자로 측정한 물리 면적이 아니라 이미지 기반 추정값입니다.
같은 스티커를 비슷한 각도에서 선명하게 촬영하고 스티커만 타이트하게 선택할수록 정확도가 높습니다.


## V3 Balanced

V2가 정상 검은 차량까지 과도하게 손상으로 판정하는 문제를 수정했습니다.

변경:
- 직접 밝기/차체색 비교보다 HOG 방향성 구조 비교를 중심으로 사용
- 흰색/검은색 차량처럼 대비가 반전돼도 영향 축소
- X/Y 크기와 위치를 자동 탐색하여 가장 잘 맞는 상태로 정렬
- 기준사진에서 구조정보가 충분한 영역만 주 판정에 사용
- 손상률은 넓은 구조 불일치 비율과 전체 구조저하를 함께 사용
- 색상은 보조지표로만 사용

실제 앱 결과 캡처 회귀시험:
- 정상 검은 SUV: 형상 약 90%, 손상 약 5%
- 훼손 검은 SUV: 형상 약 79%, 손상 약 34%

사진 각도와 사용자가 선택하는 영역에 따라 수치는 달라질 수 있습니다.


## V4 동일사진 결과 안정화

동일한 차량사진을 두 번 분석했는데 사용자가 선택한 영역 차이 때문에
손상률이 크게 달라지는 문제를 보완했습니다.

### 변경사항
1. 사용자의 자유 드래그 영역을 기준 스티커 종횡비로 자동 보정
2. 기준 영역 주변의 7개 인접 crop을 함께 분석
3. 손상률 / 형상유사도 / 색상차이는 중앙값(median) 사용
4. 분석에 실제 사용된 보정 crop 좌표를 저장
5. 동일 사진 + 동일 스티커 + 동일 알고리즘 버전은 perceptual image hash로 결과 캐시
6. 동일 사진을 다시 올리면 과거 분석값과 동일 crop을 재사용

캐시는 신규 `st_analysis_cache` 테이블만 사용합니다.
기존 st_stickers / st_rules / st_inspections 데이터는 변경하지 않습니다.


## V5 원본 스티커 + 정상부착 예시 캘리브레이션

### 관리자
스티커 A 데이터는 아래 묶음으로 관리합니다.
- 정상 스티커 원본 1장
- 정상부착 예시사진 1장 이상
- 촬영가이드 문구
- 예시사진별 실제 스티커 영역(ROI)

첫 번째 예시사진은 사용자 촬영가이드 1번으로 표시됩니다.
관리자는 예시사진 관리에서 가이드 사진을 변경할 수 있습니다.

### 사용자
1. 스티커 종류 선택
2. 정상부착 예시사진 1번으로 촬영구도 확인
3. 차량사진 촬영/업로드
4. 실제 스티커 주변을 대략 지정
5. 스티커 원본 구조와 정상부착 예시들의 정상변동 범위를 이용해 비교

### 판정 지표
- 검출신뢰도: 현재 사진에서 스티커 구조를 정상 캘리브레이션 수준으로 찾았는지
- 구조 손상지수: 정상 예시에서 안정적으로 보존되는 구조 셀 중 현재 사진에서 유의미하게 사라진 비율
- 구조 보존율: 정상 예시 구조 대비 현재 구조 보존 정도
- 색상차이: 정상부착 예시사진들과 비교한 보조 색상지표

검출신뢰도가 낮으면 손상으로 억지 판정하지 않고 `판정불가`로 구분합니다.

삭제하지 않는 데이터:
- 스티커 원본
- 정상부착 예시사진
- 판정기준

- 분석 캘리브레이션 데이터

## V11 촬영방향 자유 + 번호판/스티커 필수확인

촬영 비율과 가로/세로 제한을 제거했습니다.

### 직원 촬영조건
사진 방향은 자유입니다.
한 장의 사진 안에 아래 두 항목만 선명하게 보이면 됩니다.

1. 차량번호판
2. 점검할 홍보스티커

사진 촬영 후 직원이 두 영역을 각각 지정합니다.

- 스티커 영역: 정상 스티커 원본 + 정상부착 예시사진 캘리브레이션으로 부착상태 분석
- 번호판 영역: 사진에 번호판이 실제로 보이는지 확인용
- 번호판 영역은 대비/문자형 경계량을 이용한 간단한 노출점수를 함께 기록
- 번호판 OCR/자동 차량번호 인식은 수행하지 않음

### 촬영가이드
정상부착 예시사진 1번은 계속 사용자에게 표시합니다.
V9에서 수정한 `guide-media-frame` 방식도 유지하여,
세로/가로 예시사진과 상관없이 관리자에서 지정한 스티커 ROI가
실제 표시 이미지 위에 정확히 위치합니다.

### 비교판정
스티커 판정방식은 V5 이후 구조를 그대로 유지합니다.

- 정상 스티커 원본
- 정상부착 예시사진의 관리자 지정 ROI
- 정상 예시의 허용 변동범위
- 실제 점검사진의 스티커 선택영역

위 데이터를 이용해 검출신뢰도 / 구조 손상지수 / 구조 보존율 / 색상차이를 계산합니다.


## V12 직원 제출 / 관리자 판정 분리

직원 화면에서 자동판정 결과를 제거했습니다.

### 직원이 보는 것
1. 차량사진 촬영/업로드
2. 홍보스티커 영역 지정
3. 번호판 영역 지정
4. 제출 전 두 영역 확대 미리보기
5. 촬영영역의 크기/선명도 보조안내
6. 점검사진 제출
7. 접수번호와 제출완료 안내

직원에게는 아래 정보를 표시하지 않습니다.
- 정상 / 확인필요 / 교체권고 / 판정불가
- 종합점수
- 검출신뢰도
- 구조 손상지수
- 구조 보존율
- 색상차이
- 자동판정 findings

### 관리자
직원이 제출 버튼을 누르면 브라우저 내부에서 스티커 분석을 수행한 후
그 결과를 점검기록과 함께 저장합니다.
자동분석 결과는 관리자 점검결과 화면에서만 표시됩니다.

자동분석 자체에 오류가 발생하더라도 직원의 사진 제출은 막지 않습니다.
이 경우 관리자 결과에는 `판정불가`와 관리자 직접확인 안내가 저장됩니다.

V12에서는 기존 same-photo 분석 캐시를 사용자 제출 분석에서 사용하지 않습니다.
잘못 지정한 영역을 수정해 재제출했을 때 이전 분석값이 재사용되는 문제를 방지합니다.


## V13 제출 우선 구조

V12의 문제:
직원이 제출 버튼을 누르면 서버 저장보다 이미지 자동분석이 먼저 실행되었습니다.
모바일에서 분석이 오래 걸리거나 오류가 발생하면 점검사진이 D1/R2에 저장되기 전에
흐름이 중단될 수 있었습니다.

V13:
1. 필수 입력/선택영역 검사
2. 스티커/번호판 영역의 최소 크기·선명도 검사
3. 사진 + 선택영역을 서버에 먼저 저장 (`분석대기`)
4. 서버 저장 성공 즉시 직원에게 제출완료 + 접수번호 표시
5. STEP 02로 초기화
6. 브라우저 유휴시간에 관리자용 자동분석 수행
7. 분석 완료 시 서명된 1회성 제출 토큰으로 해당 점검기록만 결과 업데이트
8. 자동분석 실패/브라우저 종료 시에도 사진과 접수기록은 관리자 화면에 `분석대기`로 남음

따라서 자동분석 문제 때문에 직원 제출 데이터 자체가 사라지는 구조를 제거했습니다.


## V14 제출 버튼 무반응 수정

V13의 문제점을 코드 레벨에서 수정했습니다.

### 원인
V13 `submitInspection()`은 전체 함수가 try/catch로 보호되지 않았습니다.
Canvas 기반 번호판/스티커 품질검사와 상태검사가 try 바깥에서 먼저 실행되어,
이 구간에서 런타임 오류가 발생하면 직원에게 오류문구를 표시하기 전에 함수가 종료될 수 있었습니다.
또한 `S.submitting === true`인 경우 안내 없이 return하는 경로가 있었습니다.

### V14
- 제출 클릭 즉시 `제출 내용을 확인하고 있습니다` 표시
- 전체 제출 함수를 처음부터 끝까지 예외처리
- 중복 클릭 시에도 현재 제출 중이라는 안내 표시
- 제출 버튼에 `type=button` 명시
- 서버 업로드를 XMLHttpRequest 기반으로 변경
- 실제 업로드 진행률 1~100% 표시
- 고해상도 카메라 사진을 제출 직전 1800px 이하 JPEG로 재정규화
- 번호판/스티커 오류는 구체적인 문구 표시 후 STEP 04로 이동
- R2/D1 서버 오류도 사용자에게 구분 가능한 메시지 반환
- 서버 저장 성공 후에만 `제출 완료 / 접수번호` 표시
- 이후 STEP 02로 복귀
- 자동분석은 여전히 서버 저장 성공 이후 best-effort로만 수행


## V15 실제 런타임 오류 수정
V14를 실제 Chromium 브라우저로 클릭 테스트한 결과, STEP 04의 `선택영역 확인하고 제출하기`에서 `cropBoxCanvas is not defined` 런타임 오류를 재현했습니다. 이 오류 때문에 STEP 05가 열리지 않고 사용자는 버튼이 아무 반응 없는 것처럼 보였습니다.

V15에서는 누락된 `cropBoxCanvas()`를 복구하고, 제출 전 확인화면 전체를 try/catch로 보호했으며, 전역 runtime error banner를 추가했습니다. 또한 `/js/check.js?v=15.0.0` 및 CSS version query를 넣어 기존 브라우저 캐시가 이전 JS를 계속 사용하는 문제를 차단했습니다.


## V16 촬영각도 보정 + 디자인 동일성 + 부착위치

자동판정을 세 축으로 분리했습니다.

### 1. 보정 구조손상
현재 사진을 모든 정상 예시의 평균과 비교하지 않습니다.
현재 촬영사진과 구조적으로 가장 가까운 정상부착 예시사진을 먼저 선택한 뒤,
그 예시에서 이미 발생하는 촬영각도/원근/반사 차이를 빼고 남은 구조손실을 계산합니다.

손상은 단순 불일치 셀 합계가 아니라 `연속된 손상 군집`에 높은 가중치를 줍니다.
따라서 기울기 때문에 여기저기 흩어진 차이는 손상률에 적게 반영되고,
스티커 일부가 실제로 뜯겨 연속 영역이 사라진 경우에는 높게 반영됩니다.

### 2. 디자인 동일성
가장 가까운 정상 예시와 비교하여:
- 글자/로고 HOG 방향구조
- 글자 폭/간격에 영향을 받는 edge projection
- 셀별 구조 일관성
- 원본 스티커 구조 보존

을 함께 계산합니다.

가장 큰 실제 손상 군집은 디자인 비교에서 제외하여,
`뜯어진 정상 스티커`와 `멀쩡하지만 임의 제작된 다른 디자인`을 구분하도록 했습니다.

초기 기본값:
- 디자인 동일성 82% 이상 정상범위
- 82% 미만: 폰트/로고/자간/그래픽 형상 불일치 확인필요

### 3. 부착위치 유사도
정상 예시사진에서 번호판 영역까지 지정한 경우에만 계산합니다.
번호판 중심을 기준으로 스티커까지의 방향/거리/크기비를 비교하므로
사진을 더 멀리 또는 가까이 찍는 단순 프레이밍 차이는 줄입니다.

관리자:
`예시사진 관리 → 영역설정 → 스티커 영역 → 번호판 영역(선택)`

번호판 기준을 설정하지 않은 스티커는 위치 판정을 자동으로 제외합니다.

### 관리자 결과
- 보정 구조손상
- 구조 보존율
- 디자인 동일성
- 부착위치 유사도
- 검출신뢰도
- 가장 가까운 정상 예시사진 ID
- 최대 연속손상 군집
- 산발적 구조차이

를 함께 저장합니다.


## V17 정상 예시 기반 디자인 자동기준

V16까지는 디자인 동일성을 기본 82%의 고정 커트라인으로 판정했습니다.
이 방식은 정상부착 예시사진을 여러 장 등록해도 촬영각도/반사/거리 때문에
정상 차량이 70%대 디자인 점수를 받을 경우 확인필요로 오판할 수 있었습니다.

V17에서는 정상 예시가 2장 이상이면 각 예시사진을 다른 정상 예시와
leave-one-out 방식으로 교차 비교하여 실제 정상 디자인 점수 분포를 계산합니다.

자동기준:
- 정상 예시 교차점수의 중앙값
- 하위 25% 지점
- 정상 예시 최저점

세 값을 함께 사용해 촬영환경 허용마진을 적용합니다.

`threshold = min(Q25 - 6, median - 10, minimum - 3)`
단, 58~82% 범위 안에서만 사용합니다.

따라서 정상 차량 3종을 등록했다면 그 3종의 실제 촬영차이가
스티커 A의 정상범위가 되고, 관리자가 매번 82 → 75 → 70으로
수동으로 기준값을 낮출 필요가 없습니다.

정상 예시가 0~1장인 경우에만 관리자 화면의
`예시 부족 시 예비 기준`을 사용합니다.

관리자 결과에는:
`디자인 동일성 75.1% (기준 68.4%)`
처럼 실제 해당 스티커에 적용된 자동기준을 같이 표시합니다.

## V17 명칭 통일
임시 개발명칭을 제거했습니다.

- 사용자: `법인차량 홍보스티커 셀프점검`
- 관리자: `법인차량 홍보스티커 점검 관리자`
- `스티커 A 데이터 등록` → `스티커 기준 데이터 등록`
- `운전석 측면` → `운전석`
- `조수석 측면` → `조수석`

스티커 실제 명칭은 관리자에서 등록한 이름을 그대로 사용하므로
특정 로고명/스티커 A 같은 임시명칭을 코드에 고정하지 않습니다.
